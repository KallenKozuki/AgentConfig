## 核心工作流（硬性门禁）

在编写任何代码、输出代码块、修改文件或执行命令之前，**必须完成以下前置流程**。

### 一、输出排版与风格铁律（全局生效）

为了确保极高的阅读效率，无论处于何种阶段，你的输出必须严格遵守以下要求：

1. **禁止客套与废话**：严禁输出“好的”、“我明白了”、“下面为您分析”、“总结来说”等过渡性废话。直接输出核心内容。
2. **强制结构化**：优先使用无序列表（`-`）、加粗（`**`）和表格。任何连续的文字段落不得超过 4 行，超过必须换行或转为列表。
3. **无 Markdown 代码块**：在“计划与确认”阶段，严禁使用 ` ``` ` 代码块包裹计划内容（但允许使用简单的 Markdown 加粗和列表）。

### 二、前置计划与确认流程

每次接收到需求，你必须先进行复杂度自评估，并严格按照以下两种情况输出：

#### 场景 A：简单任务（单点修改、常规逻辑调整）

直接输出精简的纯文本计划，无需额外包裹，但总字数尽量控制在 200 字以内。

**【格式示例】**

> **修改点**：xxx
> **影响范围**：xxx
> **风险/疑问**：无

#### 场景 B：复杂任务（架构分析、深度排错、跨文件大改）

**不限制字数**，但必须先输出一行 `[检测到复杂逻辑，开启详细分析模式]\n`，格式如下：

**结论先行**：（一句话概括核心方案或问题根因）
**详细分析**：
- （使用多级列表展开你的分析，逻辑分明，禁止密集大段落）
**修改点**：
1. xxx
2. xxx
**影响范围**：xxx

> 上述两个场景示例中，冒号后都要先换行

### 三、强制等待与红线规则

1. **绝对停止**：在输出完上述计划后，**必须立即结束本轮回复**，等待用户回复。

3. **最小干预**：优先通过修改现有文件来解决问题，避免随意创建新脚本。

**🚨 违规判定（零容忍）**：

适用范围：`**/*.cs`

## 服务端配置文案本地化

适用范围：`**/*.cs`

适用于服务器下发的活动表、运营配置表及其他配置对象中的展示文案。

- 服务端下发稳定英文文案 key 时，使用 `L10nText.GetTbWord(key)`。
- 服务端下发简体中文原文时，使用 `L10nText.GetTbWordByZhName(zhCnText)`；语言包以该简体原文作为查找键。
- 含占位符的服务端模板，必须先本地化、再格式化：
  ```csharp
  string text = L10nText.GetTbWordByZhName(config.Desc).Fmt(args);
  ```
- 不要将服务端配置或活动表文案传给 `L10nText.GetCode` / `FormatCode`。这两个 API 仅用于客户端代码中写死的程序提示文案。
- 协议可以调整时，优先让服务端下发稳定英文 key，避免简体原文改字导致翻译匹配失效。
- 玩家名、帮会名、区服名及其他用户或服务端运行时生成的动态数据不进入本地化表；仅本地化其周围固定模板。

## C# 判空约定

适用于 C# 代码中的空值判断。

1. 协议事件回调的事件参数保证非空，不要对事件参数本身判空。例如 `PlayerVoyageOpenShipBoxEventArgs e` 不使用 `e?` 或 `e == null`
2. 协议事件参数中的 `Message` 保证非空，不要对 `e.Message` 判空；直接访问其成员
3. 自动生成的 FUI 类中，根组件实例已非空时，其自动生成且非动态加载的子组件也保证非空，不要重复判空
   - 根组件是当前界面持有的自动生成 View，例如 `view`，不是 `GRoot`
   - 动态加载的组件、运行时赋值的组件及手动持有的引用不在此保证范围内，仍应按实际生命周期判空
4. 获取配置的结果必须判空，包括本地配置和服务器下发的活动配置；配置可能缺失、版本不同步或尚未下发
5. 使用 `UIHelper.SetNormalList` 时，若 `itemProvider` 为 `null`，且 `count` 与渲染数据列表长度一致，渲染回调的索引和默认列表项类型均由列表保证
   - 直接按 `index` 访问数据列表，并使用 `item as 预期列表项类型` 转换，不要重复进行索引边界或列表项判空
   - 配置获取结果仍必须判空

示例：协议事件回调中直接使用 `e.Message.Ret`，不写 `e?.Message?.Ret`；已确认 `view` 非空时，直接使用自动生成的 `view.Mask`

## UI Controller 结构规范

适用范围：`Assets/Scripts/GamePlay/UILogic/**/*Ctrl.cs`

适用于 UI 界面的 `*Ctrl.cs` 控制器脚本。

1. UICtrl 禁止声明字段；Controller 中只保留成员函数。
2. UI 所需的状态、缓存及其他变量必须定义在对应的 UIModel 中，由 Controller 通过成员函数读写。
3. UICtrl 和对应 UIModel 均应优先使用实例成员；除非确有无状态且无需依赖实例的理由，否则不要使用 `static` 方法。
4. 每个 UICtrl 文件末尾必须依次包含以下两个 region：

   ```csharp
   #region UI交互
   // 仅放 UI 交互回调
   #endregion

   #region 事件
   // 仅放事件监听回调
   #endregion
   ```

5. `UI交互` region 仅放 UI 控件交互产生的回调；`事件` region 仅放事件监听回调。其他方法、接口或业务逻辑不得放入这两个 region。
6. 界面隐藏时，UICtrl 基类会统一停止该界面创建的定时器；`OnHide` 中不要重复调用 `TimerManager.StopTimer`，只在需要时重置 UIModel 中保存的定时器 ID 或界面状态。
7. 数据获取、配置解析、资源名计算等不依赖 UI 组件对象的接口必须定义在对应 UIModel 中，由 UICtrl 调用其结果刷新 UI
8. 刷新普通文本或富文本组件时，先读取对应 XML 配置判断是否使用模板；使用模板时，必须通过 `UIHelper.SetTextVar` 按该模板填充参数；未使用模板时，才可直接设置组件 `.text`
